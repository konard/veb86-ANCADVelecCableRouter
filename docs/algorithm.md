# Алгоритм трассировки и соответствие ZCAD `uzvcom.pas`

Разделы 4.1–4.3 задания даны заголовками, поэтому поведение перенесено из исходника ZCAD
(`cad_source/zcad/velec/uzvcom.pas`, функции `getListSuperline` и `graphBulderFunc`); отличия и допущения
перечислены ниже. Вся логика находится в `VelecCableRouter.Core` и покрыта тестами без AutoCAD.

## 4.2. Участники графа суперлинии `S`

* Отрезки трасс с `NMO_Name == S` (сравнение ordinal, как в Pascal).
* Устройства, у которых есть подключение с `SuperLineName == S`;
* головные устройства, на которые ссылается `HeadDeviceName` подключения к `S` (у ППК может не быть своего подключения);
* устройства стояков (`RiserName` задан) без подключений — общие для всех систем.

## 4.3. Граф (порядок шагов как в ZCAD)

1. Вершины устройств в точках подключения. Вершина ищется в квадрате ±eps; устройства в одном квадрате
   делят вершину (ZCAD второе устройство отбрасывает — здесь оно остаётся трассируемым).
2. `getListEdgeBreak`: устройства с одинаковым `RiserName` сортируются по `Elevation` и соединяются
   последовательно виртуальными рёбрами (`IsVirtualRiserEdge`), вес `|ΔElevation|`, при отсутствии отметки — 1
   (с предупреждением). Стояк из одного устройства — предупреждение.
3. `extendedLineFunc` + `intercept3d`: попарные пересечения отрезков, удлинённых на eps с обеих сторон.
4. `getVertexConnectSL`: концы отрезков, совпадающие (в пределах eps) с концами других отрезков.
5. `getListDeviceAndEdge`: если в квадрат ±eps конца отрезка попадает габарит устройства (или его точка
   подключения), добавляется ребро-отвод от конца отрезка к ближайшему (по точке вставки) устройству.
6. `getListEdge`: для каждого отрезка вершины внутри его прямоугольника (ширина 2·eps, удлинение eps)
   сортируются вдоль отрезка и соединяются рёбрами с весом, равным длине.

## 4.4. Маршруты

1. Устройства группируются по `(HeadDeviceName, GroupName)`; само головное устройство в группу не входит.
2. Головное устройство ищется по `NMO_Name`. Нет головного — ошибка группы; несколько — предупреждение, берётся первое.
3. Дейкстра от вершины головного (дерево кешируется на вершину). Недостижимое устройство — ошибка с handle
   и координатой, остальные устройства группы трассируются.
4. Объединение рёбер путей в дерево маршрута и разбиение его на ломаные обходом от головного:
   * ломаная продолжается через вершины с одним потомком;
   * в ветвлении её продолжает «самый прямой» потомок (максимальный косинус угла), остальные ветви начинают
     новые ломаные в точке ветвления — так кабель не дублирует общие участки;
   * ребро стояка завершает ломаную, само не рисуется; после стояка начинается новая ломаная.
5. `SimplifyCollinear`: удаляются совпадающие (ближе `1e-6`) точки и промежуточные вершины, лежащие на прямой
   соседних точек с допуском `1e-6`, если направление не разворачивается.

## Допущения

* Дуги полилиний (bulge ≠ 0) трассируются по хордам — с предупреждением; сплайновые вершины `Polyline2d` пропускаются.
* `TEMPLATE` и имена параметров сравниваются без учёта регистра; значения (`NMO_Name` и др.) — точно.
* Подключения читаются из `conn_<n>_SuperLine|HeadDevice|Group` (и вариантов с суффиксом `Name`) и из скалярных
  `SuperLineName`/`HeadDeviceName`/`GroupName`; пустой `GroupName` — группа «без группы».
* Кабель получает и `NMO_Name`, и `SuperLineName` (оба равны имени суперлинии), чтобы его видели обе схемы палитры.
* Пересечения считаются только между отрезками одной суперлинии; граф каждой системы независим.
* Ранее созданные кабели при повторном запуске не удаляются (кабели с `TEMPLATE = Cable` в построении не участвуют).
* XDATA v1 не читается (предупреждение); версия > 2 читается с предупреждением; повреждённые пары пропускаются
  с предупреждением; вложенные таблицы `{ … }` пропускаются целиком.
* Строки XDATA длиннее 255 байт UTF-8 не записываются (ошибка с указанием поля).
* Точка подключения: вложенный блок с эффективным именем, атрибут с тегом или `DBPoint` на слое
  `CONNECTOR_POINT`/`CONNECTOR_SQUARE`; глубина вложенности ограничена 16 (защита от циклов).
